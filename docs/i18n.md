# Internationalisation

How Singi handles languages, right-to-left layout and script coverage: where strings live, how to add a language, plural categories, the CSS rules that make RTL and CJK work, and what is not covered. Read it before adding any user-facing string, locale or direction-sensitive CSS.

## Status

- `locales/en.default.json` is the source of truth.
- The other files in `locales/` were machine-generated from it and have not been reviewed by native speakers. Have each language reviewed before launching a market. Pay attention to the e-commerce terms (cart, check out, sold out) and plural forms.
- Any locale without a file falls back to the English default (Shopify behaviour).
- Theme editor labels (the `{% schema %}` text) are English only, by decision. Only storefront-facing strings are translated.

## Strings

- Every user-facing string uses `{{ 'group.key' | t }}`. Never hardcode text in Liquid, JS or attributes.
- Keys are hierarchical snake_case, at most three levels deep, with sentence-case values.
- Interpolation uses `{{ name }}`: `{{ 'search.results_count' | t: count: search.results_count, terms: search.terms }}`.
- Strings needed by JavaScript are passed from Liquid as data attributes on the element (see `data-added` and `data-error` in `sections/main-product.liquid`, `data-error` in `sections/main-cart.liquid`). Never put translations in JS files.
- JSON-LD names that are user-visible (the breadcrumb "Home") also go through `| t`.

## Add a string

1. Add the key to `locales/en.default.json`.
2. Use it with `| t`.
3. Add the same key to every other file in `locales/`, translated. Key structure must be identical.
4. Run `npm run check`; `scripts/check.mjs` verifies key parity between locale files.

## Add a language

1. Create `locales/<code>.json` (for example `locales/pt-BR.json`, `locales/zh-TW.json`). Copy `en.default.json` and translate the values.
2. Keep every key and every `{{ variable }}` unchanged. Variables may move within a sentence.
3. Use the plural categories the language needs for the pluralised keys (`collection.product_count`, `search.results_count`). Always include `other`.
4. Run `npm run check`.

### Plural categories

| Languages | Categories |
| --- | --- |
| Arabic | `zero`, `one`, `two`, `few`, `many`, `other` |
| Czech, Slovak, Polish, Russian, Ukrainian, Belarusian, Lithuanian | `one`, `few`, `many`, `other` |
| Croatian, Serbian, Bosnian | `one`, `few`, `other` |
| Slovenian | `one`, `two`, `few`, `other` |
| Romanian | `one`, `few`, `other` |
| Latvian | `zero`, `one`, `other` |
| Hebrew | `one`, `two`, `other` |
| Japanese, Chinese, Korean, Thai, Vietnamese, Indonesian, Malay | `other` |
| Everything else | `one`, `other` |

These follow CLDR. If a locale file fails theme check for plural keys, adjust to the categories Shopify's validator accepts for that language.

## Right-to-left

`<html dir>` is set from `request.locale.direction` (default `ltr`). To make a layout work in both directions:

- Use logical CSS properties only: `margin-inline`, `padding-inline`, `padding-block`, `inset-inline-start`, `inset-inline-end`, `inset-block-start`, `text-align: start | end`, `border-inline-start`. Never `left`, `right`, `margin-left`, `padding-right`, `text-align: left | right`.
- Flex and grid follow `dir` automatically; avoid `row-reverse` for visual order.
- Directional icons must mirror: `snippets/icon.liquid` adds `icon--flip` to `arrow-right`, and `assets/base.css` has `[dir=rtl] .icon--flip { transform: scaleX(-1) }`. Add the class for any new arrow or chevron that implies direction. Symmetric icons (search, cart, close) do not flip.
- `.mono` and `.price` use `unicode-bidi: isolate` so numbers, SKUs and currency do not reorder surrounding text.
- Horizontal scroll areas (the mobile product gallery) use logical padding and margin so they start from the correct edge.
- Test with Arabic or Hebrew. See [testing.md](testing.md#right-to-left).

### Tracking tokens

Negative or positive letter-spacing breaks Arabic letter joining and harms CJK, Thai and Indic text. `assets/base.css` defines `--tracking-tight` (`-0.02em`) and `--tracking-wide` (`0.08em`) and sets both to `0` for `[dir=rtl]` and for `:lang(ar|fa|he|ur|ja|zh|ko|th|hi|bn|gu|mr|ta|te|ka|hy|km|lo)`. Always use these tokens instead of literal `letter-spacing` values.

Other script rules in `base.css`: `line-break: strict` for Japanese and Chinese, `word-break: keep-all` for Korean, and `overflow-wrap: break-word` on headings, paragraphs, list items, labels and summaries so long German or Finnish words do not overflow.

## Fonts and script coverage

Inter, the default body font from Shopify's font library, covers Latin scripts. It does not include Arabic, Hebrew, CJK or Indic glyphs. `snippets/tokens.liquid` adds `system-ui` to the font stack (when the font's fallback is `sans-serif`) so the operating system supplies those glyphs, per character. Text in those scripts therefore renders in the system font, not Inter, and metrics differ from Latin text. This is accepted: only Shopify library fonts are allowed, and none covers every script.

## Markets, redirects and suggestions

- **Shopify resolves the buyer's country and market** and exposes them as the Liquid `localization` object; the footer selector (`snippets/localization-selector.liquid`) is a plain `localization` form that lets a visitor choose another country or language. The theme shows no location prompt and never redirects by location ([decision 031](decisions/031-no-location-prompt-yet-shopify-resolves-the-buyers-country.md)).
- **Automatic redirection is a store preference** (Online Store > Preferences > Automatic redirection: Country/region and Language). It redirects to the market's URL on dedicated domains, changes content on shared domains, follows the browser language, skips crawlers and does not redirect EU visitors on EU country-code domains. Turn it on or off there; keep it off if you build your own prompt.
- **Shopify's Geolocation app is discontinued** (March 2025), and `/browsing_context_suggestions.json` is not documented: do not build on either.

## hreflang and locale metadata

Shopify prints hreflang automatically for the languages and markets of one store (on by default, Online Store > Preferences), so the theme prints none of those. For equivalents on other stores or domains the theme prints exactly the alternates in the metafield `singi.alternates` of the page (product, collection, page, article, or the shop for the home page): [decision 032](decisions/032-hreflang-comes-from-explicit-alternates-per-resource.md), [multi-store.md](multi-store.md). A store that uses it turns Shopify's automatic setting off, or every alternate appears twice. `og:locale` is set to the request locale code. hreflang has not been verified on a live multi-store group.

## Money, dates, numbers

Use Shopify filters (`money`, `date`, `time_tag`) which respect the locale and market. Do not format these in JavaScript.

## Merchant-written text

The cookie dialog's text is Shopify's own banner copy where it can be fetched (a real store host; translated by Shopify, edited in Settings > Customer privacy), and otherwise theme strings (`consent.*`, [decision 046](decisions/046-the-cookie-dialog-is-the-themes-and-shopifys-api-records-the-answer.md)), translated in every locale file (machine-translated, native review needed). It is a neutral description, not legal copy: a merchant edits it under Online Store > Languages > Edit default theme content, or per language in Translate & Adapt.

The label of a badge (a `badge` metaobject entry, [decision 045](decisions/045-badges-are-a-metaobject-mapped-from-tags.md)) is store content too: translate it with Translate & Adapt on the entry. The one exception is the built-in "New", which shows when the tag `new` has no entry named `new`: it is the theme string `products.new`, translated in every locale file (machine-translated, native review needed).

Text a merchant writes in theme settings (the newsletter consent note and confirmation message) or in a section's settings (the announcement bar message) is not in `locales/`. It is translated through Shopify's theme translations (Translate & Adapt), per language, and those belong to the theme (see [content-storage.md](content-storage.md)). The theme ships no default for the consent note on purpose ([decision 029](decisions/029-newsletter-consent-is-merchant-written-and-ships-no-legal-copy.md)).

## Not covered

- Theme editor labels (English only).
- A suggestion to switch market or language based on the visitor's location (a dialog). It is not built (see `todo.md`). The footer selector (`snippets/localization-selector.liquid`) is: it shows only when the store has more than one country or language, posts a plain `localization` form, and fetches a long country list on first open instead of rendering it on every request.
- Native-speaker review of translations.
