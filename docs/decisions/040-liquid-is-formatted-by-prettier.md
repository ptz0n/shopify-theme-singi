# 040. Liquid is formatted by Prettier, the first and only devDependency family

Status: accepted (supersedes the formatter row of [decision 039](039-dev-tooling-stays-dependency-free.md))
Area: developer experience | CI
Code: `.prettierrc.json`, `.prettierignore`, `package.json` (`format`, `format:check`), `.githooks/pre-commit`, `.github/workflows/check.yml`

## Context

Decision 039 declined the Shopify Liquid formatter because the first measurement rewrote `snippets/icon.liquid` and was judged unsafe. The maintainer expects many outside contributions, where a single enforced style removes whole classes of review comments, and asked for an ignore rule for the icon file. A formatter is only worth adopting if it cannot change what the storefront renders.

## Decision

Format `blocks/`, `sections/`, `snippets/`, `layout/` and `templates/*.liquid` with Prettier 3 and `@shopify/prettier-plugin-liquid`, both pinned exactly in `devDependencies` (with a lockfile).

- `.prettierrc.json`: print width 140, two spaces, **double quotes in HTML, single quotes in Liquid** (`liquidSingleQuote`; plain `singleQuote` would also rewrite HTML attributes, which nobody wants), `embeddedLanguageFormatting: off` so `{% stylesheet %}`, `{% javascript %}` and JSON schema bodies are left as written.
- `.prettierignore` lists `snippets/icon.liquid`: it is one unbroken tag with no trailing newline on purpose.
- `npm run format` writes; `npm run format:check` is part of `npm run check`, the pre-commit hook (staged `.liquid` files only) and CI.
- A one-time format pass was committed on its own, so `git blame --ignore-rev` can skip it.

## Why

- One enforced style means pull requests are about behavior, not indentation or quote marks.
- The formatter is safe only because it was proven not to change the rendered HTML; the proof is part of the record.

## Evidence

Rendered HTML of 30 dev-store URLs (home, collections, products, cart, search, pages, account) was captured before and after the format pass and compared after removing per-request values (request ids, UUIDs, timestamps, theme hash, search ids) and whitespace next to tags: **30 of 30 identical**. Two captures of the same code differ before that normalization, so the comparison needed it; formatting itself changed no text, attribute or element. The full browser suite passes after the pass.

## Alternatives rejected

| Alternative | Why not |
| --- | --- |
| No formatter | Style review comments on every outside pull request. |
| Formatter with embedded CSS/JS formatting on | Rewrites `{% stylesheet %}` bodies and drifts from the compact style the budgets rely on. |
| Single quotes everywhere | Changes every HTML attribute for no benefit; double quotes in HTML is the convention. |

## Edge cases and dead ends

- The first spike used `singleQuote: true` and flipped HTML attribute quotes on every page: found by the HTML comparison, fixed by dropping the option.
- Whitespace inside `<option>` and JSON-LD `<script>` changes (leading and trailing spaces only): browsers ignore both.
- The trailing-newline concern about `icon.liquid` was tested and a trailing newline renders identically, but the ignore rule stays: the file is generated by hand for exactly that reason and should not be touched by a tool.
- This is a dependency in a repo that had none; decision 039's "nothing to maintain" argument is weaker for tooling that contributors run daily and strong for what it removes from review. Theme files uploaded to Shopify are unchanged (`package.json` and the config are in `.shopifyignore`).

## Trade-offs we accept

- A first `npm install` for contributors, and a lockfile to keep current.
- A large one-time diff that hides older history from `git blame` unless the format commit is ignored.

## How to verify

`npm run format:check` passes; `npm run test:all` passes; an unformatted staged `.liquid` file makes the pre-commit hook fail with the command to fix it.

## Revisit when

The plugin starts rewriting rendered output, drops support for a Liquid tag the theme uses, or a contributor hits a construct it cannot format (add that file to `.prettierignore` with a reason here).
